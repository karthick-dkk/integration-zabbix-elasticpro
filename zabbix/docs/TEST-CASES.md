# ElasticPro Zabbix 7.0 modules — critical manual test-case specification

**System under test:** `http://192.168.64.13:8080/zabbix` — Zabbix **7.0.31**, Ubuntu 24.04,
PostgreSQL 16. Frontend root `/usr/share/zabbix` (there is **no** `ui/` subdirectory).

**Modules under `/usr/share/zabbix/modules/`:**

| Folder | Module id | What it is |
|---|---|---|
| `ep_clients` | `ep_clients` | Cluster Management, Roles, **Settings**, Backups + the sidebar section |
| `ep_capacity` | `ep_capacity` | *Client capacity* dashboard widget |
| `ep_resources` | `ep_resources` | *Client resources* dashboard widget |
| `ep_volume` | `ep_volume` | *Volume report* dashboard widget |
| `elasticpro` | *third party* | embeds the ElasticPro web app; creates its own **ElasticPro** menu section in `init()` |

**Audience.** A QA engineer with Zabbix Super admin and Zabbix Admin credentials and no knowledge
of this codebase. Every expected value below is taken from the shipped code; where a judgement
needs an internal number, that number is stated in the pre-condition or in
[§2 Reference values](#2-reference-values).

**Priorities.** **P1** — a failure corrupts data, hides a real alarm, or exposes a privileged
action. **P2** — a failure makes a feature unusable or silently wrong for one role. **P3** —
cosmetic, or a narrow edge.

**Conventions.** "direct URL" means type `http://192.168.64.13:8080/zabbix/zabbix.php?action=<name>`
into the address bar of a logged-in session. "Denied" means Zabbix's own
**"Access denied — You are logged in as …. You have no permissions to access this page."** page,
*not* a blank page and *not* a PHP error. All `curl` examples in §12 run from the tester's own
machine against the live host.

Everything a case compares against. Taken from the code; no paraphrase.

### 2.1 `Settings::DEFAULTS` — what ElasticPro ships (`shared/php/Settings.php`)

| Group | Key | Shipped | `clean()` range / rule |
|---|---|---|---|
| usage | `warn` | **80** | **0**–100; non-numeric → 80; then `warn = min(warn, high)` |
| usage | `high` | **90** | **1**–100 — the floor is 1, not 0: at 0 every figure is "at or above", so every cell would go red and (because the templates take their macros from here) the jump host's triggers would alarm on every cluster at once. Non-numeric → 90 |
| display | `bars` | **0** (= *Bar under the value*) | integer 0–3; anything else → 0 |
| display | `decimals_bytes` | **2** | 0–4 |
| display | `decimals_percent` | **1** | 0–4 |
| display | `decimals_plain` | **0** | 0–4 |
| export | `size_unit` | **GB** | upper-cased, must be `MB`/`GB`/`TB`; else GB |
| refresh | `capacity` | **60** | 10–3600 — **not editable on the page**; rides along on every save |
| refresh | `resources` | **60** | as above |
| refresh | `volume` | **300** | as above |
| forecast | `bad_days` | **7** | 1–36500, then `min(bad, warn_days)` |
| forecast | `warn_days` | **30** | 1–36500, then `min(warn, flat_days)` |
| forecast | `flat_days` | **3650** | 1–36500 |
| forecast | `day_text_days` | **1** | 1–**30** |
| forecast | `month_text_days` | **60** | 1–36500, then `max(month_text, day_text)` |
| forecast | `month_days` | **30** | 1–**366** |
| types | `all` | **["CI","DI","On-Prem"]** | each trimmed to 32 chars, de-duplicated case-insensitively, **at most 8**; empty list → shipped list |
| types | `default` | **On-Prem** | must be on the list; else `On-Prem` if present; else the first entry |

Other constants: `SIZE_UNITS` = `MB`→1 048 576, `GB`→1 073 741 824, `TB`→1 099 511 627 776 (binary,
deliberately, so the export agrees with the table). `WARN_MACRO` = `{$EP.USAGE.WARN}`,
`HIGH_MACRO` = `{$EP.USAGE.HIGH}`. `Settings::INHERIT` = **0** (threshold boxes).
`Settings::INHERIT_CHOICE` = `Bars::INHERIT` = **100** (selects).

**Precedence, everywhere:** host macro → widget field → Settings page → shipped default.
An override of `0` in a threshold box is "not set", not a threshold.

### 2.7 Column counts

* **Client capacity** — `capacity-widget/columns.json` holds exactly **31** columns and **only** a
  `columns` array (no `warn`, `high` or `template` keys any more). First two: `Cluster Name` (the
  host), `ES URL` (macro `{$ES.URL}`). 7 are usage columns, 8 carry a `vs` (allocated-vs-requested),
  2 carry a `usageKey` (`Devices Seen`, `Forwarder Curr.Used / Storage`), 9 are `requested`.
* **Client resources** — built from the roles: 10 fixed columns (sections `Client`, `Log delay`,
  `ES storage`, `Devices`) plus **11 per family** when nothing is split → **65** with the shipped
  roles. Splitting the ES family replaces its 11 with 5×11 = 55 → **109**.
* **Volume report** — one column per `ElasticPro client plan` item that carries a `column` tag,
  ordered by that tag's value, label = item name with the prefix `Client plan: ` stripped.

## 3. Sidebar / menu

Pre-condition for all: PF-1. The ElasticPro section is created in `ep_clients`'s
`onBeforeAction()` — i.e. while each page is being drawn, **not** at module load — and the entry
selection is re-run afterwards. The third-party `elasticpro` module creates its section in
`init()`, which runs **earlier**, so in a both-enabled install `ep_clients` must *join* that
section, never make a second one.
